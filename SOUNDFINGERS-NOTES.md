# HISE — notes de travail (génériques)

Fork HISE : `~/GitHub/HISE`, branche `custom-develop`. HISE 4.9.x. Un fix moteur du fork n'atteint un binaire qu'après rebuild de HISE **et** ré-export du plugin.

## Workflow Git (tous les projets créés avec HISE)
- `main` = branche de production. `develop` = branche de développement, reçoit les features validées.
- Feature complète : nouvelle branche basée sur `develop`, PR vers `develop`.
- Petite modif : commit direct sur `develop` toléré.
- `main` ne reçoit que des PRs depuis `develop`, une fois le build `develop` validé et prêt pour la prod.
- Fork HISE : `custom-develop` tient lieu de `develop` (mêmes règles : commits légers OK dessus, features sur branche dédiée → PR vers `custom-develop`). Ne jamais toucher `main`/`develop` du dépôt HISE (upstream Christoph Hart) — `custom-develop` existe précisément pour ne pas les confondre.
- JUCE du fork = sous-module `Matt-Dub/JUCE_customized` (remote `fork` ; `origin` = Christoph, ne jamais y pousser). Toutes les modifs SoundFingers vivent sur JUCE `custom-develop` (`.gitmodules` : `branch = custom-develop`, branche par défaut sur GitHub). Nouvelle modif JUCE : sur `custom-develop` (ou branche partie de là), push `fork`, puis commit du pointeur dans HISE `custom-develop`.
- Update JUCE de Christoph : dans `JUCE/`, `git fetch origin` puis `git merge origin/juce6` sur `custom-develop`, push `fork`, bump du pointeur dans HISE. Merge upstream HISE : le pointeur JUCE est en conflit → fusionner le commit JUCE de Christoph dans notre `custom-develop` JUCE et pointer sur ce merge, jamais sur son commit seul (sinon nos modifs disparaissent de l'export).
- Un merge qui réécrit `JUCE/projucer/Projucer.app` a échoué une fois (« Operation not permitted », bundle à moitié supprimé). Réparer par `git checkout -- projucer/`, relancer, puis `codesign --verify --deep` : l'export appelle ce Projucer (`--resave`).

## Diagnostic « l'effet ne fait rien »
1. Bon module ? Est-il bypassé (`module.isBypassed()`) ? Module bypassé, nœud Faust compilé en `process = _,_;`, paramètre parqué sur un no-op : mêmes symptômes. Bypass d'abord.
2. La dll compilée est en retard sur les sources : un `HardcodedMasterFX` joue `DspNetworks/Binaries/dll/*.dylib`, pas le XML. Éditions de réseau/nœud silencieuses tant que les réseaux ne sont pas recompilés dans HISE **et** HISE relancé. `hise_runtime_recompile` ne recharge que les scripts. Comparer mtime `.dylib` vs XML. Un `ScriptFX` interprété (souvent bypassé) ne montre que ce que disent les fichiers.
3. Lire le XML du réseau : un contrôle à `Value="0.0"` est à 0 quoi que montre l'UI.
4. Ensuite seulement suspecter le DSP ; le rendre d'abord en headless.

## HiseScript
- Tableaux = références ; seul `.clone()` copie. `reg x = Shared.arr` réécrit la source. Mais `.clone()` est profond et transforme les références de composants en `void` : copier à la main.
- `inline function` non réentrante (params/locals par fonction, pas par appel) : ne jamais relancer un callback depuis lui-même via `changed()` ; différer avec `Content.callAfterDelay`. Définir une `inline function` avant celles qui l'appellent.
- `setControlCallback` : nom d'`inline function` obligatoire (pas de littéral anonyme). Un callback partagé identifie sa source en comparant `component` à des références stockées.
- Composants créables **uniquement à `onInit`** (`Content.add*` après → erreur). Tout créer, puis `showControl()`. `onInit` a un plafond de temps (`compileTimeout` ≈ 10 s, « Script execution timed out ») : bissecter le nombre de composants, tester par rechargement de projet.
- `Content.add*` : `saveInPreset` = true par défaut → après onInit le preset restaure la valeur et **déclenche le callback** plusieurs fois. Pour un réglage global (Preferences) : `set("saveInPreset", false)`.
- `ScriptFile.writeObject()` n'atteint le disque qu'à la sortie de HISE (`loadAsObject` relit la nouvelle valeur ; tester la persistance après exit réel).
- Mots réservés : `default`. `local` ancré : `local a = …; a.data.x = v` → « Cannot assign to this expression » (2+ niveaux) ; passer par un index de tableau vivant ou recherche linéaire.
- `array != []` ne teste rien ; utiliser `.length`/`indexOf`. `.length == 13` en REPL = chaîne `"uninitialised"` : le namespace n'a jamais tourné. En cas de namespaces morts : bissecter dans l'ordre des `#include`.
- `typeof(x) == "number"` OK. Callback d'un slider pack : `value` = index, ou -1 / Object à la restauration de preset.
- `ScriptLabel` `editable` ne suffit pas dans le plugin exporté : `grabFocus()` scripté (panneau transparent `Clicks Only` par-dessus).
- `ScriptButton` n'a pas de `repaint()`. `Console.print(trace(obj))` dans un LAF/paint = coût énorme à chaque repaint.
- Boucles infinies UI : deux composants qui se `setValue`+`changed()` mutuellement → garde « valeur inchangée », pas de `changed()` si identique. Broadcasters : `setEnableQueue(true)` + rafraîchissements en masse au hover = accumulation.
- `Synth.deferCallbacks(false)` : le script tourne sur le thread audio. Dans `onNoteOn` : zéro allocation, zéro appel d'API coûteux ; tester l'appartenance (note à traiter) **avant** tout calcul ; mettre en cache ce qui vient d'un slider pack (rafraîchi par son callback, y compris preset : `registerAtParent` route tout changement vers `controlCallback`) ; hisser `getNumSliders()` hors de la condition de boucle.
- Listes d'`eventId` (`addVolumeFade`, choke) : anneau de taille fixe alloué à l'init. `HiseEventBuffer` = 256 entrées, débordement = événements jetés silencieusement ; `addVolumeFade` sans garde sur eventId mort ; `isArtificialEventActive` aliase par modulo → tester `id > 0 &&`.
- Boucles de paint dimensionnées par données utilisateur : plafonner (`Math.min`) ; remplacer boucle scriptée imbriquée par `indexOf` natif.
- Listener de `Broadcaster` qui lève une erreur à l'init → `EXC_BAD_ACCESS` au lancement de HISE (cible détruite mais encore enregistrée dans `debugInfoListeners`). Les appels initiaux du listener arrivent **après** onInit : garder par un flag armé par timer.
- Undo : `useUndoManager` sur un slider = 1 pas par drag ; `setValue` programmatique n'enregistre rien ; transaction toutes les 500 ms (`HISE_UNDO_INTERVAL`) ; `Engine.undo/redo` asynchrones. Groupes de contrôles partagés : `Engine.performUndoAction` avec paires de snapshots (l'action s'exécute une fois immédiatement : Apply diff-based). `Engine.canUndo()/canRedo()` = ajout du fork (absent en HISE stock).
- Deux `TransportHandler` (ex. humanizer + player) = stop reçu en différé, ordre non maîtrisé : n'en garder qu'un.

C++ hors réseau : rebuild IDE complet (pas la recompile de script).
- Via REST, le wizard `compile_networks` écrit `DspNetworks/Binaries/{AutogeneratedProject.jucer,Source/}`, `DspNetworks/ThirdParty/` (Faust) et `AdditionalSourceCode/nodes/`, mais **pas** `batchCompileOSX.sh` : construire à la main, HISE fermé : `Projucer --resave AutogeneratedProject.jucer` puis `xcodebuild -project Builds/MacOSX/<Projet>.xcodeproj -configuration Release` (~2 min) → `dll/<Projet>.dylib`. Tester un réseau compilé à chaud : `builder/apply` `add` `HardcodedMasterFX` puis `set_effect` (accepté, contrairement au ScriptFX). Jeu de test compilé = réseaux de test temporaires générés avec le produit, puis tout supprimer (208 fichiers non suivis) avant commit.
- Le wizard `compile_networks` régénère aussi tout le C++ Faust avec le Faust embarqué (version ≠ → ~44 000 lignes de diff sur `ThirdParty/`) : `git status` puis `git checkout -- DspNetworks/ThirdParty/` avant commit, relancer le build seul. Fixer la même version Faust sur toutes les machines.
- Nœud `project.*` (ThirdParty) = C++ compilé dans la dll projet, pas dans HISE : dll périmée → module non instanciable → `onInit` meurt au premier usage, sans lien apparent. Après merge/pull touchant `DspNetworks/` ou `AdditionalSourceCode/nodes/` : rebuild dll. Vérifier `nm -gU dll | c++filt | grep <nœud>` + mtime.
- Nœud ThirdParty : HISE ne scanne que la **racine** `DspNetworks/ThirdParty/*.h` → header stub 2 lignes `#include "sub/x.h"` pour un submodule (`src/` invisible du scanner). `node_properties.json` : `"IsPolyphonic"` = « classe `template <int NV>` » (sinon `error C3203`), n'active pas le poly. Codegen HISE 4.9.4 émet `wrap::data<project::x,` sans argument de template → `sed` en `project::x<1>,` avant chaque build (ré-appliquer après chaque codegen).
- Nouveau nœud custom : l'ajouter à `factory.cpp` et `includes.h`.
- Paramètres de nœud persistés **par index** : ne jamais réordonner, seulement ajouter. Ne pas dépendre d'un enum HISE (`TempoSyncer::Tempo`).
- ABI `OpaqueNode` : pas de hook non-realtime (les nœuds scriptnode ne reçoivent pas `nonRealtimeModeChanged`).
- Attributs de `<Network>` (défaut false) : `AllowCompilation`, `HasTail`, `SuspendOnSilence` (→ `HardcodedMasterFX::isSuspendedOnSilence()`, valeur compilée en `constexpr` dans le `.h`).
- **Suspend on silence** : suspend après `HISE_SUSPENSION_TAIL_MS` (1000) de **sortie** < −90 dBFS **et** entrée courante silencieuse ; compteur remis à 0 dès que la sortie remonte → queue jamais coupée. Désactivé en rendu offline. Les nœuds d'événements (`SN_EMPTY_PROCESS`, tempo-sync) se mettent à jour hors chemin audio. **Ne pas suspendre un réseau avec suiveur d'enveloppe / ducker / compresseur / limiteur** : état périmé au réveil → premier coup atténué ou avalé. Une charge CPU qui remonte ne prouve pas que la sortie est juste : tester à l'oreille un coup isolé après long silence. Convolution : gain réel (−25 % thread audio à l'arrêt), rien à périmer. Regarder la classe feuille avant de dire qu'un module ne suspend jamais (`EffectProcessor` base = false).
- Convolution HISE : le paramètre `Gate` n'est qu'un interrupteur, aucune détection de silence. Le coût est à ~80 % sur le thread audio (`Multithread` ne déporte que la queue). Gain d'une convolution = énergie de l'IR (`Σh²`), pas son pic : normaliser par énergie. IR rééchantillonnée si fréquence projet ≠ IR (96 kHz ≈ ×2 coût). IR/rebuild : jamais sur le thread audio (double slot + builder thread + crossfade).
- FFT : macOS = vDSP (`USE_IPP` forcé 0, `UseIPP` sans effet). Windows : IPP sinon Ooura scalaire (FFTW3 = code mort dans ce fork, sans `case` dans `AudioFFT`). Export `UseIPP=1` refusé si le binaire HISE n'a pas été bâti avec IPP. Ne jamais définir `USE_IPP=1` à la main sous Windows (`#error`). `VisualStudioVersion` ≠ « Visual Studio 2026 » → popup « VS Version mismatch » à chaque export.
- Modules natifs : un sampler inactif n'est jamais auto-bypassé (`isSoftBypassed` = drapeau explicite) : plein callback par bloc ; seul un soft-bypass explicite l'évite. Soft-bypass d'un `ModulatorSynthChain` = plus aucun rendu en dessous. `Purged` par script est dangereux : garde au niveau sampler vs drapeau par son, fenêtre `shouldSkipPreloading` pendant un chargement de preset, fall-through de `killVoicesAndCall` → silence définitif ; à ne pas utiliser sans instrumenter le fork.
- Sampler : `PreloadSize` ≥ longueur du sample → chargé entier, plus de streaming (mesure par sample : une map 8 RR × 8 couches = 64 préloads). `VoiceLimit` plancher dur 2. `setVoiceAmount` force `VoiceLimit`. `BufferSize` puissance de 2. `HISE_LOAD_ENTIRE_SAMPLE_THRESHHOLD` = contournement de clics, pas optimisation.
- `ScopedAnalyser` réel dans l'IDE, stub vide dans le plugin exporté : profil IDE surfacture les chaînes d'effets (~0,5 pt).

## Faust dans HISE (server 4.9.3 / API 0.9.2, Faust 2.77.3, macOS arm64)
- Dossier source Faust codé en dur : `DspNetworks/CodeLibrary/faust/`. L'export active Faust dès qu'il contient un fichier : aucun fichier parasite.
- Toolchain fournie dans le checkout HISE (`tools/faust/bin/faust`, `lib`, `share/faust`). Pas de `brew install faust` (second compilateur, version différente). `faust --version` n'imprime rien : `-v`. Pas de `-I` pour la stdlib. Test de compilation : `faust f.dsp -o /dev/null`.
- `libfaust` arm64 seulement : bâtir HISE arm64-only, pas universal. Vérifier un build Faust : `lipo -archs` = arm64, `otool -L` montre `libfaust`, `strings -a | grep -ci fakelib` = 0. Config : `HISE_INCLUDE_FAUST=1` + `HISE_FAUST_USE_LLVM_JIT=1` + `HISE_INCLUDE_FAUST_JIT=1` ; `=0` lie `fakelib`.
- JIT (éditeur) et export statique = deux compilateurs différents : « compile dans HISE » ≠ « s'exporte ». L'export régénère le C++ (`DspNetworks/ThirdParty/src/*.cpp`, wrappers `x_hise.h`, 3 copies) : ne pas éditer à la main. Généré avec `-ftz 0` ; HISE couvre les denormaux par `ScopedNoDenormals` dans `MainController::processBlock` (pas hors HISE).
- Pas de build CLI : un projet HISE ne se compile que via l'app desktop.
- Le nœud wrapper doit déclarer ses paramètres en `hslider`/éléments UI : HISE se lie à l'UI Faust. Des arguments de fonction n'exposent rien.
- Cœur pur + wrapper mince : DSP indépendant de HISE hors de `CodeLibrary/faust/`, chargé par `library()` depuis le wrapper (chemin relatif `../../../dsp/x.dsp`, OK en JIT et export). Jamais `import()` : il injecte le `process` du cœur (`redefinition of symbols are not allowed : process`).
- Faust émet l'UI triée alphabétiquement par label (l'espace précède les lettres : « Delay Time R » avant « Delay Time »). L'ordre vu par l'utilisateur/les presets se fixe par le binding dans HISE.
- HISE lie par **nom** de paramètre (`ParameterId="..."` sur `<Connection>`) : renommer un label Faust casse le binding.
- **HISE ignore le `init` des sliders et parque tout paramètre Faust à son MINIMUM.** Concevoir chaque contrôle pour que son minimum soit livrable, ou le placer derrière un contrôle dont le minimum = bypass (zéro exact). Un contrôle bipolaire (min = plein négatif) ne peut pas le satisfaire en Faust : le régler dans le réseau. Vaut aussi pour les paramètres scriptnode. Passe-bas à cutoff min = mur : relever `MinValue`.
- Un nœud Faust n'est testable en headless que s'il exporte une fonction dont les sliders ne font qu'alimenter (`process = gate(hslider..., ...)`) ; sliders noyés dans le corps = intestable.
- Tempo sync : `control.tempo_sync` lit le BPM hôte, pas Faust. Il pilote les paramètres Faust en `<ModulationTargets>`, pas en paramètres simples : un multiplicateur scriptnode sur la valeur est impraticable → arithmétique par paramètre dans Faust.
- Filtres/étages hors de toute récursion Faust → scriptnode ; dans le `~`, obligatoirement Faust. Boucles scriptnode : `container.fix32_block` + `routing.send`/`receive` ; le `~` de Faust ferme la récursion à l'échantillon avec 1 échantillon de retard implicite.
- Runtime Faust navigateur (MCP faustbrowser) = Faust 2.84.3 ≠ 2.77.3 de HISE : smoke test seulement, jamais preuve sur le plugin. Onglet ouvert + clic humain pour l'audio. MCP stdio, un seul serveur par port. Écoute via HISE.
- Vérifier le C++ généré avant d'annoncer un coût : `faust f.dsp -o /tmp/x.cpp` (`ba.if` → ternaire).
- Les suiveurs d'enveloppe Faust ne sont pas transparents au bit grand ouverts (float32 `1-coeff` + `coeff` ≠ 1 ; ~−2,6e-06 dB) : tester avec tolérance, jamais en égalité de bits.
- Ne pas modifier un `.dsp` ou un réseau HISE ouvert : HISE les réécrit depuis la mémoire à la sauvegarde (récupérer par `git checkout`). Si un export casse : suspecter d'abord ce qui a bougé (emplacement du wrapper, contenu de `CodeLibrary/faust/`).
- **JIT Faust (IDE) ≠ C++ exporté pour NaN/inf** : le backend LLVM de Faust marque toute opération flottante `fast` (`fcmp fast ole`, `llvm.minnum`) → l'optimiseur suppose qu'il n'y a jamais de NaN. Aucun test NaN écrit en arithmétique Faust n'est fiable dans l'IDE (mesuré : `abs(NaN) <= FLT_MAX` vrai, NaN borné à la valeur max d'un clamp ; branche NaN d'un limiteur inopérante). Le C++ exporté n'a pas ce drapeau (HISE compile sans `-ffast-math`, `-ffp-contract=off`) : un test headless clang passe là où le JIT échoue. Vérifier le non-fini sur la dll ou l'export, pas seulement en headless. Voir le code : `faust -lang llvm f.dsp`. **`ma.isnan` / `ma.isinf` gèlent HISE** : le JIT appelle `isnanf` / `isinff`, absents de libm macOS (seul `isnan` existe, et en double : appelé en float il répond 0 pour NaN) → saut à `0x0` dans `faust_base_wrapper::init()`, chargement bloqué, REST muet (`sample` le montre). Le C++ exporté, lui, émet `std::isnan` / `std::isinf` (portable). Symboles float présents sur macOS (libm + `math.h`) : `__isnanf`, `__isinff`, `__isfinitef` ; absents de MSVC.
- `ef.gate_gain_mono` au seuil minimal (−100 dB) se referme quand même sur le silence numérique et rouvre avec son attaque à chaque note : « gate ouvert » pour un null test = nœud gate bypassé.

## XML de réseau (`DspNetworks/Networks/*.xml`)
- HISE possède le bloc `<Parameters>` des nœuds. Ne jamais écrire de `<Parameter>` à la main : ils paraissent réels (éditeur, macro) mais sont des `Value=` inertes sans `Automated="1"`. Laisser `<Parameters/>` vide ; s'il reste vide après chargement, le nœud n'a pas compilé.
- `Value=`, noms et ordre des macros = état transitoire réécrit à la sauvegarde. Porteurs : `MinValue`/`MaxValue`/`DefaultValue`, structure nœuds/connexions, `ParameterId` des connexions. Ne comparer (diff) que cela ; committer le churn plutôt que le reverter.
- Valeur de départ d'un macro de réseau = son `Value`, pas `DefaultValue` : le code généré émet `this->setParameterT(i, Value)` (`snex_jit_ValueTreeBuilder.cpp`, section « Default Values ») et la métadonnée compilée lit aussi `Value` (`ParameterData.cpp`). `DefaultValue` ne sert qu'à l'éditeur (reset du slider). Poser les deux ; à la sauvegarde HISE retire `DefaultValue` s'il égale `Value` (`DspNetwork.cpp`, `stripValueTree`) : sa disparition dans un diff n'est pas une régression.
- Écrire d'autres nœuds à la main (ex. `routing.global_cable`), HISE fermé et après sauvegarde, a chargé sans souci.
- Mix : `control.xfader` en `Mode="RMS"` = équi-puissance (racine d'un fader linéaire ; `hi_dsp_library/dsp_basics/logic_classes.h`) ; `Linear` perd 3 dB à mi-course. Un attribut, intestable en headless. Un nœud alimentant un xfader doit émettre le wet seul, sinon Mix ne retire pas le dry. Jamais wet = `(dry+wet)-dry` (inexact en float).
- Lire une modulation depuis un script : nœuds `routing.global_cable` accrochés aux sorties de `pma`, lus par `getValueNormalised()`. Sur la copie bypassée/interprétée les valeurs restent statiques ; seul le module compilé bouge. Lire la sortie d'un nœud depuis un script est impossible (seulement les câbles avant lui).
- `pma` clampe à [0,1]. Pour un paramètre en Hz, l'offset LFO est linéaire en Hz et bute sur le plancher aux cutoffs bas. Moduler en log avec `control.cable_expr` (`Math.log(1.0 + input*999.0)/Math.log(1000.0)` en entrée, `20.0*Math.pow(1000.0, input)` en sortie) de part et d'autre du `pma`.
- IR de convolution lues dans `AudioFiles/` ; non versionnées = absentes d'un clone neuf.

## Defines / config projet
- `AllowDynamicSpectrumAnalyser` : enum `Dynamic=0, AlwaysOn=1, AlwaysOff=2` → **0 = analyseur actif**. Il se transforme à chaque tick même si `paint()` ne dessine pas (masquer la tuile ne suffit pas).
- OpenGL : sur macOS passe par le shim GL→Metal, `OpenGLTexture::create` à chaque frame = ~90 % du coût d'ouverture de l'UI. Le define `HISE_USE_OPENGL_FOR_PLUGIN` ne fait que fournir la valeur par défaut ; un `OPEN_GL="1"` persisté dans `GeneralSettings.xml` gagne (écrit à la fermeture de l'instance). Forcer `Settings.setEnableOpenGL(false)` en `onInit` (avant le 1er éditeur). Windows : gain léger, garder opt-in.
- `ENABLE_ALL_PEAK_METERS` : un export à 0 a perdu tous les VU une fois, pas un autre, cause inconnue ; en cas de meters absents, suspecter ce flag. Coût réel des meters : négligeable.
- `HISE_SKIP_IDLE_SYNTH_BLOCKS` (défaut 0, fork) : samplers/chaînes sortent tôt à l'idle ; idle CPU 0,87 % → 0,15 % avec suspend. Si un son ne démarre pas après silence : suspecter d'abord.
- `NUM_HARDCODED_FX_MODS` : HISE Linux sans ce flag supprime les chaînes « Px Modulation » à la sauvegarde → diff massif.
- `JUCE_USE_BETTER_MACHINE_IDS` = **option de module JUCE** (`<JUCEOPTIONS>` du `.jucer` + `AppConfig.h`), pas un define d'exporteur. IDE ≠ plugin exporté → ID machine différent → re-registration silencieuse de la licence (`update_license`, heuristiques anti-abus). Ne jamais changer après release (invalide les licences). Test : mtime du `.license` à travers IDE/hôtes ; « le plugin charge » ne prouve rien (en ligne ça se répare seul). Ne pas éditer un keyfile à la main (commentaire non signé) : installer un keyfile authentique d'une autre machine. `enc("")` (`ME2DAA8C8D`) = `getUniqueDeviceID()` a échoué (sandbox hôte). Scripts embarqués compressés : grep du binaire ne prouve rien.
- `HISE_NUM_PLUGIN_CHANNELS=48` : coût fixe (buffers effacés par bloc, matrices) payé par tous ; `MatrixData` : nombre de destinations = sources du parent ; `restoreFromValueTree` restaure la matrice **avant** les enfants (compte périmé gagne).
- `PooledUIUpdater` : 30 ms codé en dur, ~105 appelants, non réglable.
- Compiler : Windows VS2022/2026 + Projucer `--resave` + MSBuild ; macOS Xcode + `xcodebuild`. Windows incrémente le nom de la dll (`X6.dll`) ; macOS : fermer HISE avant de rebuild la dylib (mappée).

## Bugs moteur connus / correctifs du fork
- `SimpleTimer::startOrStop` : déréférence `WeakReference<PooledUIUpdater>` sans test null (crash).
- `PooledUIUpdater::timerCallback` appelait `SimpleTimer::timerCallback`/`Listener::handlePooledMessage` (pures virtuelles) sur un objet en destruction (thread de chargement de samples) → `__cxa_pure_virtual`, abort de Logic. Rendus non-purs, `isRunning` atomique.
- `MatrixData::numAllowedConnections` jamais initialisé → matrices > 2 connexions élaguées au hasard (suit l'allocateur). Défaut −1.
- Merge upstream `5ad80f27c` : sémantique du coefficient de `setGainValues` inversée ; `MatrixPeakMeter::getCoefficient(0 ms)` doit renvoyer 0.0f sinon VU-mètres figés à UpDecayTime=0.
- Soft-bypass d'un container : les `MatrixData` display values ne sont plus écrites → VU figé. Fix : `clearDisplayValues()` appelé par `ModulatorSynth::softBypassStateChanged`.
- `Helpers::FFT::transformReadBuffer` (`analyse.fft`) recréait `juce::dsp::FFT` à chaque appel (~30 Hz/nœud) → cache (moitié du CPU UI ouverte). Puis le cache par nœud coûtait ~3,1 Mo de setup vDSP par nœud (21 nœuds = 65 Mo/instance) → `064472a63` : un moteur par ordre partagé par le process (`SharedResourcePointer`), verrou par moteur (IPP/MKL non réentrants sous Windows). −74 Mo malloc à 1 instance, −77 Mo par instance en plus ; FFT OK et UI en 7 s dans Logic.
- `MasterEffectProcessor::renderWholeBuffer` ne remettait pas `numSilentBuffers` à 0 au réveil d'un effet suspendu → un delay (sortie en retard sur l'entrée) se re-suspendait et avalait l'écho. Requis pour `SuspendOnSilence` sur delay.

- `HiseAudioThumbnail::LoadingThread` : use-after-free (lit un `AudioBuffer` libéré) sur changements de preset rapides, `findMinAndMax` → 0xc0000005 sous Ableton/Windows. Pistes : debounce du changement de preset, désactiver le sample display, patch du fork. (Non tranché.)
- `MidiDropper` (drag & drop MIDI) sous Linux/Bitwig : fenêtre plugin XEmbed sans `XdndAware` sur la cible → drop ignoré (Reaper OK). Repli : bouton d'export vers un dossier.
- `ScriptingApi::Synth::addVolumeFade` : voir HiseScript. `Engine.setOutputBusName(idx,name)` = ajout du fork.
- Wrapper AU JUCE (`AudioProcessorChangedUpdater::update`) traitait `parameterInfoChanged` en synchrone sur le thread message ; HISE en émet un par contrôle UI lié à un paramètre (`MacroControlledObject::rebuildPluginParameterConnection`) → 1 `kAudioUnitProperty_ParameterList` par contrôle, l'hôte reconstruit tout l'arbre de paramètres à chaque fois (Dread Drumz : 1290 × 645 params, UI à ~35 s dans Logic, hôte > 100 % CPU ensuite). ## Méthode de profilage
- **Échantillonner tous les threads et diffuser (UI ouverte − fermée) avant de choisir un suspect.** Deux sessions perdues sur le thread message ; le coût réel était le thread « Pool » d'OpenGL.
- Bruit : ~70 échantillons sur ~500 actifs du thread message sont dans l'erreur de `sample` à 1 ms ; ne pas poursuivre en dessous de ~150. Dérive de baseline : vérifier que le gain apparaît aussi UI fermée.
- Un patch qui « fonctionne » (vérifié au désassemblage) peut ne gagner aucun temps mur. Ne pas toucher au cœur du dispatch/événements HISE sans gain mesuré (friction de merge upstream, a déjà cassé les meters).
- Le profil au repos ne voit pas les coûts proportionnels à la densité de notes (gigue, allocations) ; ni les convolutions permanentes (constantes, elles s'annulent dans un delta UI ouverte/fermée).
- Mesurer avant d'optimiser : tuiles meters, paint/LAF (`internalRepaintUnchecked` ≈ 0), `ModulatorChain` vides, chaînes de pitch voice-start : non coûteux.
- Ne pas asserter « vérifié identique sur N fichiers » sans lire les N.
